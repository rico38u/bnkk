# Black 1 — مشروع اجتماعي متعدد الملفات

مشروع الواجهة الأصلية **Black 1** بعد تقسيمه إلى ملفات مستقلة، مع تبويب جديد للبحث عن المستخدمين والمحادثات الخاصة اللحظية باستخدام Supabase.

## ما الذي يعمل؟

- الحفاظ على واجهة Black 1 الأصلية (الاستكشاف، الريلز، البث، الحساب، الإعدادات وغيرها).
- تقسيم الواجهة إلى `index.html` وملفات CSS وJavaScript وأصل الفيديو.
- إضافة تبويب **الرسائل**، والبحث عن طريق الاسم أو اسم المستخدم، وقائمة المحادثات، ومراسلة مباشرة بتحديثات لحظية.
- تسجيل الحسابات عبر Supabase Auth مع البريد الإلكتروني وكلمة المرور.
- حماية ملفات المستخدمين والرسائل بسياسات قاعدة البيانات (RLS)، وعدم إظهار البريد الإلكتروني عند البحث.
- نشر تلقائي عبر GitHub Pages باستخدام GitHub Actions.

> **مهم:** الحسابات والمنشورات القديمة في الملف الأصلي كانت محفوظة محليًا في المتصفح. بعد الربط، تصبح الحسابات والرسائل الخاصة مشتركة بين الزوار. أجزاء المحتوى المحلية الأصلية لم تُنقل تلقائيًا إلى قاعدة بيانات مشتركة.

## 1. إعداد Supabase (مرة واحدة)

1. افتح [Supabase](https://supabase.com/) وأنشئ مشروعًا جديدًا.
2. من **SQL Editor** افتح `supabase/schema.sql` والصق محتواه كاملًا ثم اضغط **Run**.
3. من **Project Settings → API** انسخ **Project URL** و**anon / publishable key**. لا تستخدم `service_role` أو أي مفتاح سري في الواجهة.
4. افتح `assets/js/config.js` وبدّل:
   - `https://YOUR-PROJECT.supabase.co` برابط مشروعك.
   - `YOUR_SUPABASE_ANON_KEY` بمفتاح anon/publishable.
5. من إعدادات **Authentication → URL Configuration** أضف رابط الموقع الذي ستنشره إلى **Site URL** و**Redirect URLs**. مثلًا: `https://USERNAME.github.io/REPOSITORY/`.
6. لتسهيل تجربة التسجيل، يمكنك إيقاف تأكيد البريد من إعدادات Auth مؤقتًا؛ والأفضل إبقاؤه مفعّلًا عند الاستخدام العام.

بعد ذلك سيستخدم الموقع التسجيل والدخول عن بعد، ويمكن للمستخدمين البحث عن بعضهم وبدء محادثة. سيظهر تنبيه إعداد في تبويب الرسائل إذا لم يُضبط Supabase.

## 2. نشر الموقع على GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub.
2. ارفع جميع ملفات هذا المجلد إلى جذر المستودع، وتأكد من وجود `index.html` في الجذر.
3. ادخل **Settings → Pages** واختر **GitHub Actions** كمصدر النشر. يوجد سير عمل جاهز في `.github/workflows/pages.yml`.
4. انتظر نجاح سير العمل في تبويب **Actions** ثم افتح رابط Pages الذي يظهر في إعدادات المستودع.
5. أضف رابط Pages نفسه إلى إعدادات Supabase في الخطوة السابقة.

إذا كنت تعمل من الهاتف، يمكنك فك ضغط الملف، ثم رفع الملفات إلى المستودع من واجهة GitHub أو عبر تطبيق/محرر يدعم Git.

## 3. التجربة المحلية

افتح المشروع عبر خادم محلي بدلًا من فتح `index.html` مباشرة. مثلًا باستخدام Python من مجلد المشروع:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000`. من دون بيانات Supabase ستبقى الواجهة الأصلية في وضعها المحلي، وستوضح صفحة الرسائل أن البحث والدردشة العامة يحتاجان إلى إعداد الخدمة.

## تنبيهات الأمان

- لا تضع كلمة مرور قاعدة البيانات ولا مفتاح `service_role` داخل JavaScript أو GitHub.
- مفتاح anon/publishable يمكن وجوده في الواجهة، بشرط تطبيق سياسات RLS الموجودة في ملف SQL.
- لا تشارك ملفاتك المحلية القديمة إذا كانت تحتوي على بيانات شخصية مضمّنة في منشورات أو صور.
- راجع حدود التخزين والاستخدام لدى Supabase قبل إطلاق الموقع لجمهور كبير؛ هذا المشروع جاهز كبداية قابلة للتوسعة وليس بديلًا عن اختبار حمل احترافي.
